# Curse of Strahd — Campaign Bible

The campaign bible, split from one 260 KB markdown file into small files so that AI tools (and people) only read what a question needs. The repo is also laid out as a Jekyll site (just-the-docs theme) for GitHub Pages. **Read the visibility warning below before turning Pages on.**

## Read order for AI tools

1. `current-state.md`: one-page snapshot of the party and open threads.
2. `entity-index.md`: name → file lookup, with aliases. Or `grep -ril '<name>' npcs pcs sessions`.
3. Open only the files the question needs.
4. Before editing anything, read `conventions.md`. It holds the canonicity rules.

## Layout

```
index.md            site home page
current-state.md    one-page snapshot (hand-maintained)
entity-index.md     generated by tools/build_index.py
conventions.md      former Sections 2 (tone) + 8 (maintenance/canonicity rules)
open-questions.md   former Section 14
changelog.md        dated one-liners of canon changes
about.md            former Section 1 and the document preamble
items.md            former Section 5 (Key Items); entries are short, so one file
templates.md        former Section 6 (prompt templates)
tech.md             former Section 7 (Foundry VTT)
pcs/                one file per PC
npcs/               one file per NPC; npc-template.md is the blank template
sessions/           s00.md … s10.md; online RP as s00-5a.md, s05-5.md, etc.
lore/               former Sections 9–12, one file each
prep/               current prep (former Section 16)
archive/            superseded prep (former Sections 13, 15) + the original monolith
tools/              split / lossless-check / index scripts
```

**Strahd's Brides** stays as one file (`npcs/strahds-brides.md`), with Ludmilla, Anastrasya and Volenta as subsections, as in the original. Session 9's `npcs/woodcutters-bride.md` is the same person as Ludmilla and is cross-referenced by alias.

## Frontmatter

Every file has YAML frontmatter, so `grep` can stand in for reading:

```yaml
title: "Isaac \"Izek\" Strazani"   # display / nav title
name: ...                          # original heading
aliases: ["Isaac", "Izek"]
type: npc        # pc | npc | item | session | lore | prep | meta | section
status: mixed    # canon | idea | mixed (heuristic: "mixed" = contains an IDEA tag)
last-session: 10 # highest "Session N" mentioned in the file
parent / nav_order / has_children   # just-the-docs navigation
```

`status` and `last-session` were generated by a heuristic during the split. Correct them by hand as needed.

## Maintaining

- After adding or renaming a file, run `python3 tools/build_index.py` to regenerate `entity-index.md`.
- New NPC: copy `npcs/npc-template.md` to `npcs/<slug>.md`, and add frontmatter with `parent: "NPCs"`.
- New session: `sessions/sNN.md` with `parent: "Session Log"`, `session: NN` and `nav_order` one higher than the last. Then update `current-state.md` and `changelog.md`.
- Canonicity tags must be kept exactly as written. In the source they appear markdown-escaped, as `\[IDEA — NONCANONICAL\]`.

## How the split was made

`tools/split_bible.py` cut `archive/campaign-bible-monolith-2026-10-10.md` on its headings without rewriting any prose. `tools/check_lossless.py` confirmed that all 1,640 non-blank source lines appear exactly once across the split files. The only line that moved is the trailing `*Last updated:*` footer, which now lives in `changelog.md`.

## ⚠️ GitHub Pages visibility

On GitHub Free and Pro, **a Pages site is public even when the repository is private.** This bible contains GM-only secrets (spies, hidden survivals, planned encounters). If players could find the URL, either:

- keep the repo private and don't enable Pages (browse it on github.com instead, which also renders the markdown); or
- use GitHub Enterprise Cloud, where Pages can be restricted to members; or
- publish only a player-safe subset.

Local preview, without publishing anything: `bundle install && bundle exec jekyll serve`.
